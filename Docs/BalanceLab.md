# Обновление лаборатории 0.7.0

Новый режим «Миры · выпуск 0.7»: пять кирок × три локации × начало / 25% / 75% ветвей × два способа управления, затем три стратегии развития профиля по шесть игровых часов. При 8 seed — 744 задания. Реальный лимит до двух часов. В физических сравнениях способности считаются открытыми; в кампаниях их требуется купить по правилам профиля.

Кампании покупают минимальную подготовку типов кирок (3 уровня урона/прочности с уровня профиля 3, 5 с уровня 4), затем следуют выбранной стратегии. Подготовка оплачивается по обычным рецептам. Приоритет — недостающая накопленная добыча для профиля, затем материалы покупки; оба маршрута строятся постепенно. Это воспроизводимая эвристика, не идеальный игрок.

`DefaultBalance.asset.locations` задаёт слои, прочность, плотность руд и жидкости. Можно передать полную JSON-конфигурацию в существующее поле/CLI `--balance`; mode 6 тоже передаёт её каждому заданию. Manifest schema 6 отделяет новые результаты от старых. Локация входит в идентификаторы сценариев, отчёты и сравнения; ресурсы CSV перечисляются динамически.

Команда из корня проекта:

    Builds/BalanceLab/PickaxeFallBalanceLab.x86_64 -batchmode -nographics -noaudio --lab-cli=worlds --plan=/абсолютный/путь/worlds-0.7.0-plan.json --output=/абсолютный/новый/отчёт

Файлы: `report.html`, `summary.csv`, `profile-levels.csv`, `profile-blockers.csv`, `profile-maps.csv`, `structures.csv`, `benches.csv`, `purchases.csv`, исходные `results.jsonl` и manifest. Цель калибровки — медиана пятого уровня 210–270 минут, не меньше 80% профилей за шесть часов. При малом числе seed результаты предварительные.

Ниже — документация прежних режимов. Исторический профиль 0.6 описан в [Progression060.md](Progression060.md); текущий отдельный профильный режим использует шесть часов и все маршруты.

# Balance Lab

Локальная программа для Linux, использующая игровую физику PickaxeFall. Сервер, Python и дополнительная подписка не нужны. Изменять баланс программа не будет: она измеряет результат текущего кода и настроек.

Режим «Профиль · 3 часа» проверяет уровни, обязательную прокачку и строительство: [Progression060.md](Progression060.md).

## Подготовка и запуск

В Unity открыть **PickaxeFall → Balance Lab → Build and Open**. После первой сборки можно запускать `Builds/BalanceLab/PickaxeFallBalanceLab.x86_64 -noaudio` отдельно от редактора. Приложение имеет собственное окно; работники запускаются без графики.

После изменения игрового кода или `DefaultBalance.asset` пересобрать лабораторию тем же пунктом меню. Отпечаток включает код, настройки баланса, Unity, настройки физического времени, PNG кирок и параметры их импорта (они задают физический контур). Устаревшая сборка блокирует новый запуск из окна; старые отчёты доступны для просмотра. При сборке из изолированной копии параметр `--lab-source-project=/путь/к/исходному/проекту` задаёт расположение исходников для проверки свежести.

Нажать **Новый анализ**. В начале будет оценка скорости, затем прогресс и примерное время до полного покрытия. Не закрывать окно, если прогон должен продолжаться. **Стоп** сохраняет завершённые задания; **Продолжить** запускает оставшиеся. Новый лимит времени отсчитывается при каждом продолжении.

## Режимы

| Режим | Проверки по умолчанию |
|---|---|
| Быстрый | Первый уровень, изолированно, 17 применимых навыков и 10 пар на каждую кирку; 8 карт, оба бота, 15 минут |
| Все пары | Первый/средний/максимальный уровни, изолированно и на фоне общей прокачки; 32 карты |
| Все тройки | Полный перебор троек с одиночными и парными опорами; 32 карты, без общего лимита времени |
| Свой набор | Заданные уровни 25 ветвей, сравнение с отсутствием улучшений |

Быстрый режим содержит **480 сценариев / 3840 заданий-карт**. Полный парный — **14160 / 295680**, тройной — **98760 / 3160320**. Вероятностные ветки отряда и спасения могут увеличивать число реальных физических забегов до четырёх на задание. Длинные режимы могут занять часы или дни. Взвешенные сочетания навыков разных типов кирок восстанавливаются из необходимых результатов каждого типа, без дублирования заведомо одинаковой физики.

Работников по умолчанию половина логических ядер, максимум шесть; число можно изменить. При нехватке ресурсов ПК уменьшить его. Лимит времени не гарантирует завершение всех сценариев: сохранённая часть отчёта показывает фактическое покрытие.

Точки уровня: 1, `ceil(max/2)`, max. Урон и прочность учитываются по текущему типу кирки, включая возможные повышения на верстаке. В общей прокачке остальные навыки уже на той же стадии: строки показывают отключение выбранных навыков.

## Что измеряется

- Метров глубины, секунд спуска, блоков и ударов.
- Каждый из тринадцати ресурсов и стоимость продажи всей добычи; монеты за разрушение сами не начисляются.
- Доход в минуту с восемью условными секундами меню за раунд.
- Кирки, верстаки, действия и срабатывания случайных эффектов.
- Среднее, медиана, диапазон и доля ограниченных забегов. Лимит одного забега — 600 игровых секунд в быстром режиме, 1800 в остальных.

В деталях строки показываются цена покупки уровней от нуля до выбранного, материалы и их упущенная продажная стоимость. Условная окупаемость = полная стоимость / дополнительный доход в минуту. Она показывается только при положительной нижней границе 95% интервала, а не при любой положительной случайной разнице.

Одинаковые карты используются для опорного и изменённого набора. Интервалы вычисляются парным bootstrap на 1000 повторов. До восьми общих карт оценка предварительная. У редких эффектов дополнительно выводится недостаток срабатываний; нулевой результат на малой выборке не означает бесполезность.

**Матрица пар:** дополнительный эффект `AB − A − B + база`, в монетах/мин. Положительное значение означает выигрыш сверх суммы отдельных эффектов. На общем фоне тот же расчёт использует четыре соответствующих отключения. Тройки сравниваются с лучшей входящей парой; на общем фоне сравниваются потери от отключения.

**По рулетке** вычисляет ожидаемую стоимость и время по всем пяти шансам выпадения, затем их отношение; это не среднее арифметическое доходов/мин. Требуются общие карты всех пяти типов.

Размер отряда без шанса отряда отмечается как зависимый навык. Энергетические улучшения без жестов не получают искусственной пользы. Шанс отряда и последний шанс считаются через условные исходы с весами реальной вероятности. **Диагностика: эффекты 100%** предназначена для проверки механизма; её результаты и окупаемость нельзя смешивать с обычным анализом.

## Боты и физика

Пассивный бот не использует жесты. Активный впервые действует через две секунды, затем проверяет возможность действия каждые 0,2 с, после успеха выдерживает только 0,5 с реакции. Ищет боковой верстак, сундук или ценную руду в радиусе 3,2 м; учитывает препятствия, лаву и необходимость ремонта, иначе применяет пробой вниз. Это фиксированная стратегия, а не идеальный игрок.

Работники считают шаги по 1/60 с подряд, без ожидания реального времени. У игры и работников общие часы и физический шаг `GameController.SimulateMiningStep`. Обычная игра вызывает его в `FixedUpdate`; работник выполняет шаги подряд. Звук, частицы, меню и запись игрового профиля выключены. Карты и эффекты имеют фиксированные seed; случайные эффекты используют независимые потоки. Каждая вероятностная ветка создаёт новый локальный `PhysicsScene2D`. Простого удаления объектов недостаточно: внутреннее состояние мира Unity способно менять повторный забег. Мир выгружается между заданиями, материалы освобождаются сразу. Воспроизводимость проверяется в одной версии Unity на одной платформе: совпадение траекторий между Android и Linux не обещается.

## Отчёты и обновления

Результаты находятся в `Builds/BalanceLab/Results/<дата-id>`: настройки, отпечаток сборки, сценарии, `results.jsonl`, журналы работников, экспортированные `summary.csv` и `report.html`. Это локальные артефакты, исключённые из Git. HTML открывается без сети; в нём есть фильтр и раскрывающиеся детали.

Для сравнения изменений открыть новый отчёт, ввести папку предыдущего и нажать **Загрузить для сравнения**. Сопоставляются одинаковые уровни и общие seed; разные стратегия, Unity, диагностический режим или лимит забега делают отчёты несовместимыми. Старый отчёт не продолжается новым движком: создаётся отдельный анализ.

В отчёт записываются также цены продажи, накопленная цена каждого уровня и вероятности эффектов. Просмотр истории использует этот снимок экономики, а не текущие цены из кода. У предварительных отчётов без снимка цены помечены как недоступные.

При аварии незавершённый последний JSONL-фрагмент сохраняется отдельно, а его задание выполняется заново. Законченные результаты не дублируются. Работники принадлежат только текущему приложению, личный профиль игры не загружается.

## Командная строка

```bash
./Builds/BalanceLab/PickaxeFallBalanceLab.x86_64 -batchmode -nographics -noaudio --lab-cli=quick --seconds=900 --workers=6 --output=/полный/путь/к/новому/отчёту -logFile /tmp/balance-lab.log
```

`--lab-cli=full` и `--lab-cli=triples` выбирают длительные режимы. `--samples=32` задаёт число карт. `--resume=/путь/к/отчёту` продолжает сохранённый анализ с тем же отпечатком. Проверки расчётов и физики: `--lab-checks`; сравнение пакетного исполнения с выполнением шагов по кадрам: `--lab-parity`. Параметр `--plan=/полный/путь/plan.json` загружает собственную конфигурацию; пример структуры сохраняется в каждом отчёте. Само окно и интерфейс не входят в Android APK.

- Четыре пакетных и выполняемых по кадрам забега совпали точно по времени, глубине и каждому ресурсу: дерево без жестов, дерево с жестами, камень с бережным ударом, алмаз с энергетическими улучшениями.

- Остановка после 53 заданий и продолжение до 280 сохранили исходные записи без дублей. Отдельно проверены обрезанный последний фрагмент и отказ продолжать отчёт с другим отпечатком.
- Обычная Linux-сборка прошла 90 игровых проверок в портретном окне 540×960. Android IL2CPP APK собран; классы лаборатории и протокол работников в его метаданные не попали.

Контроль производительности на Ryzen 5 7535HS (12 логических ядер), шесть работников: расширенный быстрый набор на 64 карты завершил **17 920 заданий / 19 840 физических веток за 762 с (12 мин 42 с)** при лимите 15 минут. Во время расчёта работники занимали примерно по 120 МБ, управляющее приложение — 109 МБ. Это измерение физического движка; снимок цен добавлен после этого прогона и проверен отдельно. Скорость длительных режимов зависит от уровней улучшений, числа кирок и длины забегов; переносить эту скорость на все тройки без калибровки нельзя.

## Изменения модели 0.4.0

После верстака характеристики берутся у текущего типа, поэтому для старта деревом значимы также улучшения камня/золота/железа/алмаза. Планировщик включает будущие достижимые типы (25/23/21/19/17 ветвей по стартовым типам) и подписывает материал в названии навыка. Быстрый набор: 480 сценариев × 8 карт = 3840 заданий. Все пары: 14 160 сценариев; все тройки: 98 760. Ограниченный бюджет сохраняет готовые результаты.

Формат отчёта schema=3: 12 материалов при сохранённых ID, CSV включает изумруд/лазурит/красную пыль/аметист. Старые журналы с восемью ресурсами открываются с нулевыми новыми слотами; продолжить старый физический прогон нельзя. Активные физические сценарии рассматривают уже открытые приёмы; экономический hourly-probe оплачивает открытия и учитывает их в лимите покупок.

## Аудит прогрессии 0.5.0

В списке режимов выбрать **Аудит прогрессии**. По умолчанию 32 карты и 120 минут. Для этого режима допускается только положительный бюджет до 120 минут. Полный перебор сочетаний не запускается.

В стандартном наборе **557 сценариев / 17 776 заданий**:

1. Все пять кирок, оба бота, без верстаков / только ремонт / полная генерация: 960 заданий.
2. Отдельные независимые карты, 320 заданий. Их seed не пересекаются с настройкой.
3. Три стратегии развития за час: кирки, приёмы, добыча; 16 последовательностей каждой, 48 заданий. Это час настоящих покупок, не все улучшения, выданные бесплатно.
4. Первый/средний/максимальный уровни всех ветвей и целевые пары. Сначала выполняются восемь общих карт каждого сценария, затем покрытие расширяется до 32.

Улучшения личного урона/прочности проверяются на своём типе. Общие навыки — на дереве, железе и алмазе. Размер отряда отдельно сравнивается с таким же заранее купленным шансом отряда; иначе навык нельзя оценить. Максимум всей прокачки проверяется для всех пяти типов.

Горизонт обычного сценария — 600 игровых секунд, максимальной общей прокачки — 1800, часовой стратегии — 3600 с учётом восьми секунд меню между раундами. Ограничение записывается в каждой строке; сравнение отбрасывает пары с разными горизонтами. Это технические отсечки лаборатории, в игре лимита времени забега нет. Последний незавершённый спуск часового сценария отмечен censored=1 как граница наблюдения, а не зависание.

CLI:

```bash
./Builds/BalanceLab/PickaxeFallBalanceLab.x86_64 -batchmode -nographics -noaudio --lab-cli=audit --samples=32 --workers=6 --seconds=7200 --output="$PWD/Builds/BalanceLab/Results/my-audit" -logFile /tmp/pickaxefall-audit.log
```

Отдельный полный JSON GameBalance можно передать через `--balance=/абсолютный/путь/balance.json` без пересборки. Сначала соберите актуальный код; образец JSON находится в поле balance файла manifest.json. В отчёте сохраняется именно переданная конфигурация и её цены, а не цены сборки. Внесение изменений в исходный asset или код по-прежнему требует новой сборки.

Отчёты schema=4 дополнительно содержат `benches.csv` с ремонтами и `purchases.csv` с каждой покупкой. В HTML перечислены фактически завершённые этапы, глубина/время P10/P50/P90/P95, износ от лавы, затраты энергии, прочность перед ремонтом и вероятность следующего ремонта по глубинам. Терминальные визиты ещё живой кирки при отсечке исключаются из оценки выживания между ремонтами. Квантили учитывают веса физических веток, а не усредняют редкое спасение с обычным исходом.

Остановка сохраняет готовые задания; продолжение не запускает их повторно. Неполное покрытие явно отмечено, недостающие результаты не превращаются в нули. Старые отчёты с 8/14 слотами ресурсов открываются с нулевыми новыми материалами; другая схема или отпечаток запрещают продолжение старого физического расчёта.

Повторный экспорт завершённых измерений без физического запуска:

```bash
./Builds/BalanceLab/PickaxeFallBalanceLab.x86_64 -batchmode -nographics -noaudio --lab-export="$PWD/Builds/BalanceLab/Results/my-audit" -logFile /tmp/pickaxefall-export.log
```

Исходный manifest и результаты не меняются; analysis.json записывает версию анализатора. Полная диагностическая прокачка показывает суммарную цену уровней; в сравнении размера отряда заранее купленный шанс остаётся общей предпосылкой, а не ценой первого уровня шанса.

## Аудит 0.8.0

Режим «Миры и навыки · 0.8» / `--lab-cli=worlds`: три карты, пять кирок, оба управления, три фона прокачки, четыре новых навыка отдельно и в сочетаниях на двух ступенях. Для сочетаний со старыми навыками добавлены их одиночные контроли. При восьми сидах — 15 624 задания, в том числе 24 кампании по шесть игровых часов. Задания чередуются по сидам, чтобы ограниченный по времени запуск не потратил весь бюджет на одну группу. Лимит времени обязателен и не превышает двух часов.

`skill-benefits.csv` содержит время в жидкостях, сохранённую в лаве прочность и бонусы земли/сундуков. В HTML эти показатели есть в подробностях каждого сценария. Цена материалов учитывается как упущенная выручка. Редкие эффекты требуют просмотра числа срабатываний и условий применения.

История с 25 ветвями и 17 потоками вероятностей открывается с нулями для новых навыков; сохранённые цены остаются прежними. Продолжать старый прогон новой сборкой нельзя.
